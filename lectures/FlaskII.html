Template Inheritance

Most web applications will have the same elements on different pages (i.e. header, nav bar, footer etc).... so instead of re-making the same element from scratch on different pages, or even in different sections - we can use Jinja to help us :)

Jinja has a template inheritance feature that specifically addresses this.

The idea is that you can move the parts of the page layout that are common to all templates to a base template, from which all other templates are derived.

Then we use {% extend "base.html" %} and {% extend block %} statements to extend these reusable aspects to other pages.

So lets set up a small example:

In this template, we use the block control statement to define the place where the derived/child templates can be injected . Blocks are given a unique name, which child templates can reference when they provide their content.

So, with the base template (base.html) in place, we can now create an index.html that will inherit from base.html.
Add to your project, a new file called index.html, - put into the templates folder, and then add the following:

 


{% extends "base.html" %}

{% block content %}
    <h1>Hi, We are using inheritance :)!</h1>
    <section class = "flex-intro">
   <p> A BD </p>
    </section>
{% endblock %}

{% extends "base.html" %}

{% block content %}
    <h1>Hi, {{ user.username }}!</h1>

    {% for item in passedDictionary %}

Since the base.html template will now take care of the general page structure, we need to only have the content part in the index.html.

The extends statement establishes the inheritance link between the two templates, so that Jinja knows that when it is asked to render index.html it needs to embed it inside base.html.

The two templates have matching block statements with the name content, and this is how Jinja knows how to combine the two templates into one.

URL Links with Templates

Flask comes with a super convenient url_for() helper function that allows us to easily connect other template pages or files within our templates.
So far, if we would have wanted to connect one html file to another, we would have had to hardcode in the url to that html file.. :( - not very flexible...
So the url_for() will change all that!

We will start with linking to other templates: So lets go back to our base.html with the nav bar, and recall the following:

 
 
 <li><a href="/index">Home </a></li>
  <li><a href="/about">About </a> </li>

So - these links currently do not work. ... and now we will use the url_for() to link to the correct views: -
Recall in your main.py - you have the routes & their associated functions ... it is these functions that we will refer to.
So replace with:

 

   <li> <a href="{{url_for('index')}}">Home </a> </li>
   <li> <a href="{{url_for('pineAppleA')}}">About</a> </li>

And tadah! links are working

Next - we can use the url_for() helper function to also link to static files (images etc...)

We will edit the path for the img ref in pineAppleChild_B.html. So first, we will remove the hard coded path in main.py and replace with: 

 

return render_template("pineAppleChild_B.html",
                           passedImg = "pineapple_2.jpg" )
And then in pineAppleChild_B.html, we can specify the link using the url_for(): 
 
  
     <img src = "{{url_for('static' , filename ='images/'+passedImg)}}"/>

Note: here because we are linking to a static file - we need to pass also the top level folder that it is located in, and then the second parameter is the file name.

Template Inheritance

Most web applications will have the same elements on different pages (i.e. header, nav bar, footer etc).... so instead of re-making the same element from scratch on different pages, or even in different sections - we can use Jinja to help us :)

Jinja has a template inheritance feature that specifically addresses this.

The idea is that you can move the parts of the page layout that are common to all templates to a base template, from which all other templates are derived.

Then we use {% extend "base.html" %} and {% extend block %} statements to extend these reusable aspects to other pages.

So lets set up a small example:

MORE ON HTTP METHODS

The most conventional method for getting data from the user is via an HTML form. And so that is what we just did in the previous example :)

We will now go a little more in detail into the various HTTP methods and their usage within the Flask Framework.

We already know: that in order to send data to the server, an HTTP request must be made by a client (i.e. web browser).

The two most common HTTP methods for packaging the data that we want sent as part of the HTTP request: is POST and GET.

*GET* FEATURES

  • A GET request encodes the form parameters in the URL, in what is called a query string.
  • With the GET method, we can send data ONLY in form of pairs (KEY => VALUE).
  • When data is sent from a form with the GET method: the data to be sent is visible to everyone (displayed in the URL).
  • The GET also has limits on the amount of information to send. The limitation is 2048 ASCII characters.
  • However, because the variables are displayed in the URL, it is possible to bookmark the page.
  • Never send sensitive data using the GET protocol!

*POST* FEATURES

  • Data sent from a form with the POST method is invisible to others: all names/values are embedded within the body of the HTTP request.
  • There no limits on the amount of information to send when using POST.
  • Moreover POST supports advanced functionality such as support for multi-part binary input while uploading files to server.
  • Because the variables are not displayed in the URL, it is not possible to bookmark the page.

So in Flask, there are different methods to handle HTTP requests.
By default, the Flask route responds to GET requests - as we have by default implemented up until now.
However, you can change this preference by providing method parameters for the route () decorator. Let's add to our current project a registration form ... Note we will not yet save any of the data ... and we will not do any authentication/or error handling .... (but we will do a bit in future classes).
The point of this form will be to demonstrate using the POST method :)

    This data can be recovered using the GET/POST Methods.
    Here is a partial list of some important properties and what they contain:
    • request.method: Returns the HTTP method used for the request (e.g., "GET", "POST", "PUT", "DELETE").
    • request.url: Provides the full URL of the requested page.
    • request.form: A dictionary-like object containing data submitted in the request's form, typically used for POST requests.
    • request.args: A dictionary-like object containing query parameters passed in the URL, commonly used for GET requests.
    • request.files: A dictionary-like object holding information about any files uploaded in the request.
    • request.cookies: A dictionary-like object containing any cookies sent with the request by the client.
    • request.data: Returns the raw, buffered request body, useful for handling non-form data like JSON or XML.
    • request.json: If the request body contains JSON, this attribute automatically parses it into a Python dictionary or list.
